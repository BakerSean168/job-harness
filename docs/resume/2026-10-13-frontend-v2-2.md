## Remaining verification / explicit limitations

- The Repository confirms the highlighted *code exists*. It **does not independently prove who implemented each part**. The user must review individual ownership and be prepared to demonstrate it. The enterprise `krjx` record still requires independent verification of employment, dates and responsibilities.
- MemoFlow has its earliest visible Git commit in December 2024, although historical Library says January 2024. This is **not proof of a false date**, but its start date should be checked against contemporaneous records before external submission.
- The live endpoints `memoflow.bakersean.top` and `body.bakersean.top` returned HTTP 200 in prior inspection. **HTTP 200 does not constitute visual E2E confirmation** that every new 3D/multi-tab workflow is already live and accessible. Confirm an authenticated demonstration separately.
- Existing project `links[].url` values in the canonical ResumeLibrary are stored as strings beginning with `GitHub: https://`. The current PDF renderer prints the project string as text, not as an actual PDF link annotation. This was already present in previous versions. **We intentionally did not modify the shared link data or redeploy the renderer during the v2.2 profile-only task**. A separate renderer/content migration is required for properly clickable project links. The global GitHub contact link in the header is clickable.
- Formal output is a **candidate review draft**, not an automatically submitted application. No source claims of business traffic, percent improvements, or other unverifiable metrics were added.
