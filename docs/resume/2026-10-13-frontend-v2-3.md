## 目的及范围

将 `ai-frontend-v2-2` Revision #6 作为冻结来源，创建新的 **`ai-frontend-v2-3` Profile**，而不是继续覆盖原有 Profile 或重写不可变 Revision。

变更项目：

1. 修复 ResumeLibrary 中 MemoFlow 与 BodySense 两个历史错误链接：由 `GitHub: https://...` 修复为规范的 `https://...`，显式增加 `label=GitHub` 与项目 Showcase URL。
2. 在独立 opt-in 模板 `compact-project-links-v2` 中渲染两个可点击项目入口：`GitHub · 项目展示`，带 `noopener noreferrer` 与严格 HTTP(S) URL 白名单。兼容旧 revision 里的 `GitHub: https://...`，不改变旧模板。
3. 对 v2.3 的两个项目标题压缩成 `知行 MemoFlow` 和 `BodySense`；原有产品简介、项目贡献、真实日期/角色保留。仅在 v2.3 展示层移除冗余的 `(持续维护)`，不修改原项目的历史事实。
4. 新 Profile 的四条专业技能对齐普通前端要求：JavaScript / TypeScript / HTML5 / CSS3、Vue 3 / React 组件、状态与异步、工程及 UI/UX。
5. 仅新模板移除多余 `项目亮点：` 标签，直接保留加粗的贡献标题；保持原始黑白设计语言，不缩小字号。
6. 更新 v2.3 documentTitle / PDF filename / HTML meta description 为适合正式求职的正向描述；旧版本输出元数据保持不变。
7. 结合项目公开 Showcase，独立检查真实 UI 截图证据。如截图来自测试环境或原型，**必须标注来源，不能视为真实生产业务指标/用户数据**。

## 独立渲染器发布边界

Oracle2 的 Job Harness Compose 位于 `~/projects/my-infrastructure/etc/server/oracle2/job-harness/compose.yaml`。渲染器容器是 **renderer**，使用 `job-harness-renderer:oracle2` 镜像；Server / Web / Boss Bridge 共用 **其他定制镜像**，不得对全组运行 `up --build`。正式构建仅使用 `docker compose ... build renderer` 和 `up -d --no-deps renderer`。发布前打独立的旧镜像回滚 Tag；健康检查或渲染失败时回滚 `renderer`。
