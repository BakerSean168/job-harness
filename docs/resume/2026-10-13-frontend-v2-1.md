# Frontend Resume v2.1 · One-page draft and UI/UX rationale

Date: 2026-10-13

## Objective

Generate a **new, independently addressable, review-only frontend resume** based on the current `ai-frontend-v2` Profile, preserving all existing v1/v2/v3 Profiles, Revisions, Artifacts and Job Harness recruitment configurations. The original frontend v2 remains the baseline and is unchanged.

The purpose is **not** to market the candidate as a UI/UX designer. For frontend roles, Figma/Penpot are supporting evidence of prototype-to-component collaboration. The highest-value differentiators remain business interaction correctness, asynchronous state handling and concrete engineering problem solving.

## Canonical data and reproducibility

Generator: `scripts/resume-frontend-v2-1.mts`.

- Mode `preview`: reads current `primary` Library and `ai-frontend-v2`, additively prepares project presentations `one-page-v2-1`, creates Profile `ai-frontend-v2-1` in memory, validates canonical references and calls Job Harness' PDF renderer; **no Profile or Library persistence**.
- Mode `commit`: fails closed if `ai-frontend-v2-1` exists; checks source optimistic versions and inserts the new Library presentations + single Profile **in one SQLite transaction**. Only one additional ResumeLibrary version is recorded; historical project presentations are not overwritten.
- Profile-local skill, internship and project-highlight overrides are used for custom wording; no existing canonical Library skill/work/highlight content is rewritten.
- Staging PDF/JSON: `/data/resume-frontend-v2-1-staging` (Oracle2 Job Harness server container). Exported formal PDF: `/home/ubuntu/.local/share/job-harness/data/resumes-v2-1/卢楼豪-前端开发工程师-v2.1.pdf`.
- Do **not** re-run `commit` after creation; it will correctly refuse duplicate ID. Later edits go through Profile-native optimistic updates and new immutable Revisions.
