## 选材理由

1. **前端版先放 BodySense**：GPU 颜色 ID 拾取的 3D 人体交互比 MemoFlow 更抓眼；第二条用可恢复 SSE 流，回应前端岗普遍要求的流式 AI 交互。MemoFlow 取类型化 Agent 事件流与“AI 以语义动作填写原生表单 + fencing 租约”，体现人机协同 UI。
2. **全栈版先放 MemoFlow**：Mastra 持久化工作流 + 确定性 ID 幂等写入、MCP + OAuth scope 只读网关，都是端到端服务端设计；BodySense 取事务化运行事件/租约回收与契约优先（OpenAPI/Protobuf + CI 破坏性变更检查 + 测试规模）。
3. **Agent 版先放 BodySense**：Agent 配置不可变版本化 + 评测门禁 + 影子/金丝雀灰度、LangGraph interrupt + Postgres 检查点 + 红旗护栏；MemoFlow 取 suspend/resume 工作流与工具分级审批/默认拒绝。
4. **合并版**：每个项目各取一条“全栈可靠性” + 一条“Agent/流式交互”。
5. **不写**：已上线、准确率、行数、FPS、用户量；不写“独立开发”（仓库有早期协作者，待本人确认）。唯一数字为“6 个只读业务工具”与“1500+ 自动化测试”（80fdfcd27 实测 Go 570 / Python 676 / Vitest 293）。

## Authoring 实现

文件：`scripts/resume-v4-roles.mts`（在 server 容器 `/app` 下 `node_modules/.bin/tsx` 运行）。

- `check`：只读；校验 4 个 Profile ID、4 个 presentation ID、12 个 highlight ID 均不存在；校验来源 Profile 版本（v2-2=v6、fullstack-v3=v1、agent-v3=v1）；`validateResumeProfileReferences` + `resolveResume`，并断言每份恰好 2 项目 × 2 亮点。
- `preview`：同上 + 官方 `/api/v1/resume/preview/pdf` 渲染，写 `/data/resume-v4-roles-staging/<id>.pdf`，不写 DB。
- `commit`：一个 SQLite 事务内，再次核对 live Library 与来源 Profile 与准备时完全相等、目标 Profile 不存在，然后 upsert Library（+1 版本）与 4 个 Profile。任何 v4 实体已存在则在事务前拒绝。
- `publish`：对每份调用 first-party `POST /resume/profiles/:id/revisions`（expected Profile/Library 版本）与 `POST /resume/revisions/:rid/artifacts {kind:pdf}`，下载 Artifact 内容导出到 `/data/resumes-v4/<pdfName>.pdf`，校验导出与 Artifact SHA256 一致，拒绝覆盖不同内容的已存在文件。
