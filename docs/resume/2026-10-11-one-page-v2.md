## 生成与复用

脚本：`scripts/resume-one-page-v2.mts`。该脚本是**一次性、明确目标 ID 的迁移脚本**，不是自动定期任务。

在已配置依赖的 Job Harness 容器内，脚本可先运行 `tsx scripts/resume-one-page-v2.mts preview` 生成未持久化的 PDF 预览到 `/data/resume-v2-staging`。仅在正式备份数据库、核查 Profile ID 未存在且预览验证通过时执行 `commit`，其操作会以乐观并发方式新增 Library 内容，再经 Store Port 以事务创建三份 Profile，默认不允许覆盖重名 Profile。

本次写入前的备份：

`/home/ubuntu/.local/share/job-harness/backups/job-harness-pre-resume-v2-20261011.sqlite3`

备份使用 SQLite 在线 backup API 生成，`PRAGMA integrity_check = ok`，备份前 Profile 总数为 5，写入后为 8。

正式版本经过 Job Harness `resume_revision_publish` 创建不可变 Revision，再通过 `resume_revision_artifact_materialize(kind=pdf)` 构建 Artifact。用户应在 Job Harness 简历管理界面管理/导出这些版本，不要绕过 Revision 直接替换历史投递附件。

**将来制作 V3**：复制脚本、使用全新 Profile ID / presentation ID / highlight ID 及版本名称，再预览、校验和发布。不要直接重跑 `commit`（相同 ID 会拒绝覆盖），也不要将新 Profile 自动加入活动 Campaign，除非用户明确要求修改投递策略。
