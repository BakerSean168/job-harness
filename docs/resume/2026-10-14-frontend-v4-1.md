## 面向普通前端岗位的两项目、四亮点

| 项目 | 亮点及准确表达 | 采用理由 |
| --- | --- | --- |
| 知行 MemoFlow | **复杂工作台交互：** 实现会话 / AI / 业务面板三栏协作，支持窄屏聚焦、多 Tab 保活和拖拽调宽，并以组件测试验证交互。 | 直接体现 Vue 3 复杂状态及布局交付；继承 v2.3 已核验措辞 |
| 知行 MemoFlow | **人机协同编辑：** 基于类型化语义动作将 AI 输出逐步投影到原生目标表单，结合 fencing 租约与人工接管，阻止过期 AI 覆盖用户编辑。 | 从单纯 SSE 展示提升至真实业务表单联动、并发编辑治理 |
| BodySense | **三维人体拾取：** 通过 GPU 颜色 ID 离屏渲染及深度测试拾取可见人体区域，支持点选、框选、画笔标注，并联动身体记录与 AI 提问。 | GPU 实现机制可追问，兼顾用户价值；不虚构 FPS/速度指标 |
| BodySense | **可恢复流式对话：** 对 POST SSE 事件进行 JSON Schema 校验，经 reducer 增量渲染文本、追问和工具卡片；网络中断后按事件序号补拉恢复。 | 真实异步 UI、类型安全与网络故障恢复机制，避免和 MemoFlow 重复 |

**选材取舍：** 主投 Vue/通用前端优先展示 MemoFlow，再展示 BodySense。当前不把 Mastra 内部状态持久化、MCP/OAuth、Go CAS 租约、Agent 灰度晋级混入这份前端单页；这些留给全栈/Agent 方向的独立简历。

## 源码证据（GCP 仓库 `origin/main`）

### MemoFlow

- Vue 工作台：`packages/app-vue/src/layouts/shell/AppShell.vue`；`AppShell.spec.ts` 的 Panel 保活、窄屏 focus、可调分栏与输入焦点恢复测试。

- 竞态防护测试：`useAIGoalWorkflow.spec.ts` 包含「没有服务端租约不能修改原生字段」和「租约过期则停止后续 AI 投影/保存」等案例。此处准确表述是**防止过期 AI 覆盖用户编辑**，不是声称 AI 能无条件自动写入正式目标数据库。

### BodySense

- GPU：`apps/web/src/features/body-canvas/scene/surfacePicker.ts` 通过 WebGLRenderTarget、逐部位 Color ID 材质、depthBuffer 和 readRenderTargetPixels 进行像素级拾取；对应 `BodyCanvasScene.tsx` 与 `apps/web/e2e/body-canvas-v3.spec.ts`。
- POST SSE：`apps/web/src/features/consultation/hooks/useSSEProcessor.ts` 以共享 `@bodysense/contracts` 的 `parseStreamEvent` 校验 JSON Schema 派生结构并分发事件；`useAssistantChatRuntime.ts` 的 `reduceActiveTurnEvent`、`recoverDurableRunEvents` 和 `afterSeq`；`useSSEProcessor.test.ts` 验证序列处理/回放。
- **证据边界：** 源码/测试可证明机制实现，不能推出「最新 V2 已全面生产验收」「线上 3D 功能全流程已验证」或可量化的 3D 性能优势。公开 Showcase 中的 Penpot 3D 画面仍应标注原型。

## 对比结论

旧前端 **V4** 的源码亮点更深，但使用 `classic-v1` 且 PDF 中项目链接不可点击。旧前端 **v2.3** 的模板/链接和基础技能较好，但部分项目亮点仍停留在通用工作台或 Three.js 名称。**v4.1 采用 v2.3 的成熟规范 + V4 的可信技术深度**，不修改任何旧版本，仍然便于将来根据 JD 做 Vue 优先或 React 优先的独立衍生。
